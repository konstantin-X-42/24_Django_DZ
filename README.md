# Django-проект: Онлайн-каталог товаров <img width="137" height="41" alt="Skypro" src="https://github.com/user-attachments/assets/ac708293-d4d3-4222-980d-a89643052ae0" />

Учебный веб-проект на базе фреймворка **Django**, реализующий структуру сайта-каталога интернет-магазина с интеграцией динамических моделей данных, кастомных скриптов управления, административной панели и СУБД PostgreSQL.

## 🛠 Выполненные задачи (Критерии проверки)

### 1. Перевод проекта на Poetry и изоляция окружения
* Осуществлен переход с `pip`/`requirements.txt` на современный менеджер зависимостей **Poetry**.
* Все пакеты проекта зафиксированы в конфигурационных файлах `pyproject.toml` и `poetry.lock`.
* Виртуальное окружение развернуто в изолированной папке `.venv` внутри корня проекта.

### 2. Подключение СУБД PostgreSQL и безопасность данных
* База данных SQLite успешно заменена на промышленную объектно-реляционную СУБД **PostgreSQL** с использованием драйвера `psycopg2-binary`.
* Все чувствительные данные конфигурации (секретный ключ Django `SECRET_KEY`, доступы к базе данных, статус отладки `DEBUG`) полностью вынесены в переменные окружения.
* Создан файл конфигурации персональных доступов `.env` и обезличенный шаблон `.env.sample` для проверяющих наставников.
* В файл `.gitignore` добавлены правила исключения локальных файлов окружения (`.env`) и временных баз данных из репозитория GitHub.

### 3. Разработка архитектуры моделей (Работа с БД)
* Созданы и связаны между собой Django-модели:
  * **`Category`** (Категория товаров): наименование, описание.
  * **`Product`** (Продукт): наименование, описание, изображение (`ImageField` с интеграцией библиотеки `Pillow`), категория (`ForeignKey` с каскадным удалением), цена за покупку, дата создания (`auto_now_add`) и дата последнего изменения (`auto_now`).
* Настроены читаемые отображения объектов через методы `__str__` и заданы понятные русскоязычные наименования полей и таблиц через мета-классы (`verbose_name` и `verbose_name_plural`).
* Сгенерированы и успешно применены миграции для выстраивания схемы данных в PostgreSQL.
* Проведена интерактивная проверка CRUD-запросов к СУБД через консоль `Django Shell` с интеграцией оболочки `IPython`.

### 4. Настройка панели администратора (Django Admin)
* Все разработанные модели зарегистрированы в файле `admin.py`.
* Для модели **`Category`** настроен вывод полей `id` и `name`.
* Для модели **`Product`** настроен информативный вывод колонок (`id`, `name`, `price`, `category`), добавлена фильтрация элементов по категориям (`list_filter`), а также сквозной поиск по наименованию и текстовому описанию товаров (`search_fields`).

### 5. Автоматизация работы с фикстурами (Кастомная команда)
* Базовый набор тестовых данных экспортирован в JSON-фикстуры с принудительной кодировкой UTF-8 через флаг `-Xutf8`.
* Разработана собственная консольная команда управления **`fill`** (путь: `catalog/management/commands/fill.py`).
* Логика команды автоматически выполняет два последовательных шага при вызове:
  1. Полностью зачищает таблицы продуктов и категорий в базе данных, предотвращая дублирование или конфликты связей.
  2. Загружает актуальные данные из файлов фикстур напрямую в СУБД PostgreSQL.

### 6. Выполнение дополнительных заданий (Повышенная сложность)
* **Динамический каталог:** Контроллер главной страницы `home_view` переписан на извлечение реальных данных из БД. Добавлена выборка последних 5 добавленных товаров (`order_by('-id')[:5]`) с дублированием списка позиций в консоль сервера терминала.
* **Модель обратной связи и контактов:** Создана дополнительная модель **`ContactInfo`** для управления контактными данными компании из админки. Налажен динамический рендеринг этих переменных на странице «Контакты» вместо жестко захардкоженного HTML-текста.

## 🚀 Инструкция по запуску проекта

### 1. Клонирование репозитория
```bash
git clone <ссылка_на_твой_репозиторий>
cd 23_Django_DZ
```

### 2. Настройка файлов окружения
Создайте в корневой директории проекта файл **`.env`** на основе шаблона `.env.sample` и заполните его своими локальными данными:
```env
SECRET_KEY=django-insecure-your-actual-secret-key
DEBUG=True

DB_NAME=имя_вашей_базы_данных_в_postgres
DB_USER=имя_пользователя_postgres
DB_PASSWORD=ваш_пароль_от_postgres
DB_HOST=localhost
DB_PORT=5432
```
*Примечание: Перед запуском миграций убедитесь, что база данных с указанным именем `DB_NAME` уже создана в вашей СУБД PostgreSQL (через pgAdmin или SQL-шелл).*

### 3. Установка зависимостей и активация окружения через Poetry
```bash
# Установка всех пакетов, зафиксированных в lock-файле
poetry install

# Активация виртуального окружения проекта
poetry shell
```

### 4. Применение миграций к PostgreSQL
```bash
python manage.py migrate
```

### 5. Наполнение базы данных тестовыми фикстурами
Запустите кастомную команду для автоматической очистки таблиц и загрузки демонстрационных товаров:
```bash
python manage.py fill
```

### 6. Создание суперпользователя для доступа в админку
```bash
python manage.py createsuperuser
```

### 7. Запуск сервера разработки
```bash
python manage.py runserver
```
После запуска проект будет доступен в браузере по адресу: [http://127.0.0](http://127.0.0), а панель управления администратора по адресу: [http://127.0.0admin/](http://127.0.0admin/).
